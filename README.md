# heytea-dashboard · 喜茶华南战区运营数据看板

> 每周追踪华南一区 / 华南二区门店评分数据与排名，支撑运营动作。
> 纯前端 HTML 交互看板，数据全内联，双击即可离线打开；支持多周期切换与自动更新。

---

## 功能亮点

- **区域周报总览**：华南战区 / 一区 / 二区核心 KPI + 各区 **Bottom 5** 门店
- **门店全景排名**：单一门店明细表，按筛选条件展示门店；指标表头可点击展开二级指标
- **督导视图**：按督导查看“督导表现”与“门店明细”两个表格
- **多周期切换**：右上角“数据周期”下拉，可在不同数据期之间切换
- **多层级多选筛选**：区域、城市（省份-城市树形多选）、督导、平台均可多选
- **指标口径注释**：评分类指标带问号说明，鼠标悬停即可查看计算公式
- **实时更新**：本地服务自动检测新增数据文件夹，只重建对应期，页面无需手动刷新
- **轻量品牌化**：喜茶图形 logo 内嵌 favicon 与顶栏，单文件即可分发

### 核心指标（16 个，按渠道）

| 渠道 | 指标 |
| --- | --- |
| 美团（8） | 美团评分、复购率、商品满意度、包装满意度、复购率指标得分、食品安全负反馈率、消息回复率得分、服务负反馈率 |
| 闪购（8） | 闪购评分、商责取消率、口味满意度、包装满意度、复购率指标得分、食品安全负反馈率、消息回复率、服务负反馈率 |

- **区域周报总览 KPI**：美团评分、复购率、闪购评分、商责取消率（4 个）
- **Bottom 5 表**：同上 4 个指标，按末位取 5 家门店
- **督导视图**：美团展示「商家评分 / 消息回复率」，闪购展示「商家评分 / 消息回复率 / 商责取消率」
- **异常阈值**：评分 < 4.5、商责取消率 > 0.3% 时，该单元格标浅红（`#FBF1EF`）

### 指标口径

| 指标 | 口径 |
| --- | --- |
| 综合体验分 | 商品质量分 × 80% + 服务体验分 × 20% |
| 商品质量分 | （商品满意度 × 30% + 包装满意度 × 10% + 复购率得分 × 20% + 食品安全负反馈率得分 × 20%）÷ 80% |
| 服务体验分 | （消息回复率 × 10% + 服务负反馈率 × 10%）÷ 20% |
| 商品 / 口味 / 包装满意度 | 近 60 天所有计分评价的加权平均 =（1×一星 + 2×二星 + 3×三星 + 4×四星 + 5×五星）÷ 总评价数 |
| 复购率 | 统计周期内产生复购的顾客占比，越高越好 |
| 商责取消率 | 商家责任导致的订单取消占比，越低越好 |

## 技术栈

- 纯 **HTML + CSS + JavaScript**，无前端框架，无需后端依赖
- 数据：`data.json`（构建期由 Excel 汇总，页面内联）
- 字体：正文 `Noto Sans SC`，数字 `Inter`，品牌标题 `Noto Serif SC`
- 配色：暖白 `#F9F8F6` + 白 `#FFFFFF` + 墨黑 `#1A1A1A` + 低饱和茶绿 `#45684A`，改善 `#5E7E5A` / 恶化 `#BE554B` / 无变化 `#A3A09A`
- 部署：Git + Netlify 自动构建

## 数据源

按周期新建文件夹，命名格式固定：

```text
双周基础数据MMDD-MMDD/
├── 评分数据/
│   ├── 全国评分数据8月-美团.xlsx      # 华南汇总 / 督导维度 / 华南门店维度
│   ├── 全国评分数据8月-闪购.xlsx      # 华南汇总 / 督导 / 华南门店维度
│   └── 有公式/                        # 原始带公式文件，脚本会自动跳过
└── 基础数据/                          # 可选，仅用于补门店 ID / 门店类型
    └── 双周基础数据MMDD-MMDD.xlsx
```

例如：`双周基础数据0824-0830`。

> - 文件夹名里的日期决定周期，页面右上角“数据周期”会自动列出所有期。
> - 指标数据**全部取自 `评分数据` 文件夹**；`基础数据` 只做门店 ID / 门店类型的补充，缺失时不报错（类型记为「未知」）。
> - 找不到门店基础信息时以评分数据中已有的门店为准，门店按**门店名**匹配。

### 取数口径（0 基列号）

| Sheet | 键列 | 数据起始行 | 说明 |
| --- | --- | --- | --- |
| 华南门店维度 | 门店名 = 第 5 列 | 第 6 行 | 美团评分 G/H 列（本期/上期），复购率 P/Q 列；二级指标仅有本期 |
| 华南汇总 | 城市名 = 第 3 列 | 第 5 行 | 指标列比门店维度各**左移 1 列**（如美团评分 = F/G 列）；`战区` 行为战区行，`影响分数` 行跳过 |
| 督导维度（美团）/ 督导（闪购） | 督导名 = 第 1 列 | 第 3 行 | 本期 / 上期 / 变化**三元组**，起始列 2、5、8、11、14、17、20 |

**已知特例（脚本内已做处理，勿轻易改动）：**

- 闪购督导表最后一组（第 20–22 列）是**比率**而非 0–5 分，与门店级口径不一致 → 不取该列，闪购「服务负反馈率」改由旗下门店聚合。
- 闪购督导表**没有商责取消率** → 由该督导旗下门店聚合。
- 闪购 `华南汇总` 战区行**没有商责取消率** → 按城市门店数加权平均补齐。
- 闪购文件目前**没有上期数据** → 闪购指标环比显示「—」，下一期补齐后自动生效。
- 闪购 `华南门店维度` / `华南汇总` 的 **P/Q 列（本期·上期消息回复率百分比）不使用**，看板取的是 N 列「消息回复率（10%）」得分。
- 闪购 `华南分类型` sheet 暂未使用。

## 本地使用

### 一键启动

双击 `启动看板.bat`。首次启动会重建数据（约半分钟），随后自动打开：

```text
http://127.0.0.1:8000
```

### 手动启动服务

```bash
python server.py               # 默认端口 8000，自动打开浏览器
python server.py --port 8080   # 改端口
python server.py --no-open     # 不自动打开浏览器
```

### 更新数据

把新的 `双周基础数据MMDD-MMDD` 文件夹放进本目录，服务会自动检测：

- 只重建**变动的那一期**（增量构建，更快）
- 无需手动刷新，页面自动更新
- 首次出现的新文件夹会自动构建，并加入“数据周期”下拉
- 删除某一期文件夹后，该期会从 `data.json` 中移除

## 部署

### 方式一：Git + Netlify（推荐，链接固定）

仓库已通过网络钩子接入 Netlify，`push` 到 `main` 即自动构建：

```bash
git add -A
git commit -m "更新看板"
git push origin main
```

Netlify 会执行 `python generate_html.py` 生成 `dashboard.html`，再复制到 `部署_Netlify/index.html` 作为发布目录。

也可以双击 `推送更新.bat` 一键完成“重建 + 提交 + 推送”。

### 方式二：Netlify CLI / 拖拽

双击 `发布_Netlify.bat`：重建数据并复制 `dashboard.html` 到 `部署_Netlify/`，然后：

- 已安装 Netlify CLI：自动执行 `netlify deploy --prod`
- 未安装：手动把 `部署_Netlify` 拖到 [app.netlify.com/drop](https://app.netlify.com/drop)

> 注意：Drop 每次上传会生成**新链接**；要覆盖旧链接请使用 CLI 或 Git 自动部署。

### 方式三：腾讯云 COS / 阿里云 OSS

详见 [`腾讯云COS部署步骤.md`](腾讯云COS部署步骤.md)。要点：

1. 运行 `build_data.py` 与 `generate_html.py` 生成 `dashboard.html`
2. 在 COS / OSS 创建存储桶，开启**静态网站托管**
3. 上传 `dashboard.html`，设置 `Content-Type: text/html; charset=utf-8`
4. 若仍被浏览器下载，确认响应头**不含** `Content-Disposition` / `x-cos-force-download`
